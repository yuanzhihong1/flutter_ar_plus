# 平台与能力限制

`flutter_ar` 专注于单张人脸与 Flutter Scene 内容叠加，不是完整的通用 AR 引擎。接入前请确认
以下边界符合应用需求。

## 平台

| 平台 | 状态 | 说明 |
| --- | --- | --- |
| Android | 支持 | 建议 API 24 及以上；需要相机与 Flutter GPU |
| iOS | 支持 | 建议 iOS 15.0 及以上；需要相机权限与 Flutter GPU |
| macOS | 支持 | 建议 macOS 12.0 及以上；需要相机权限与 Flutter GPU |
| Linux | 不支持 | 依赖链未提供稳定相机与推理路径 |
| Windows | 不支持 | 依赖链未提供稳定相机与推理路径 |
| Web | 不支持 | 依赖链未提供稳定原生推理路径 |

不支持平台会报告 `ArViewErrorCode.unsupportedPlatform`。

## 人脸追踪

- 同一时间只处理一张人脸。
- 需要人脸在画面中清晰可见，并具备合理光照。
- 大幅遮挡、快速运动、极端角度和远距离会降低稳定性。
- 脸宽、距离和头部姿态是估算值，不适合作为测量仪器。
- 当前帧只是采样结果，不能替代医学、身份认证或高精度生物识别方案。
- 表情系数由 MediaPipe 模型和版本决定，不同版本的关键名或质量可能变化。

## 相机

- 通常需要真机测试；模拟器可能没有可用相机。
- 应用进入后台时相机停止，恢复前台后重新初始化。
- 其他应用占用相机时可能初始化失败。
- 设备方向变化需要由相机与 Flutter 嵌入层正确传递，测试时应覆盖目标方向。
- 自定义相机预览或图像处理必须保持与追踪输入一致的镜像语义。

## 场景与深度

- `hitTest` 只检测 Flutter Scene 中的几何体。
- `unprojectPoint` 假设目标位于指定距离的平面，不执行真实深度测量。
- 没有平面检测、世界追踪、环境网格、遮挡或 LiDAR 深度能力。
- 相机画面只作为背景预览，不参与场景射线检测。
- Flutter Scene 的能力与平台限制同样适用于人脸节点。

## 文本与 Widget

- `WidgetComponent` 需要 Flutter GPU 和纹理捕获。
- 频繁重建 Widget 或使用非常大的捕获尺寸会增加 GPU 与内存开销。
- 某些平台或渲染后端可能对纹理尺寸和格式有限制。
- 需要跨平台稳定的复杂内容时，优先考虑网格、材质或预渲染资源。

## 隐私与合规

`flutter_ar` 本身不上传相机图像，但应用仍可能通过日志、截图、录屏、崩溃上报或自定义网络
逻辑暴露敏感数据。应用开发者应：

- 明确说明相机用途并只在授权后访问。
- 不记录原始帧或人脸关键点日志。
- 对调试截图和测试素材进行脱敏。
- 遵守目标市场的隐私、生物识别和数据处理法规。

## 版本兼容

`0.x` 阶段仍可能调整公开 API。生产项目应：

- 固定依赖版本范围并提交锁文件。
- 阅读 `CHANGELOG.md` 后再升级次版本。
- 在真实目标设备上回归相机、权限和渲染。
- 不要依赖 `lib/src/`、原生通道名或未文档化行为。
